# GitHub Release Automation Implementation Plan

> **For implementers:** Execute this plan task-by-task. Do not commit unless the user requests it.

**Goal:** Publish one signed, notarized, and stapled universal macOS DMG plus its SHA-256 checksum to a draft GitHub Release whenever a matching `v*` tag is pushed.

**Architecture:** Use one `macos-latest` GitHub Actions job bound to the `release` environment. The job validates the tag against all three project version declarations, runs the repository quality gates, imports the Developer ID certificate into an ephemeral keychain, lets Tauri sign/notarize/staple the `.app`, then explicitly notarizes and staples the generated DMG to work around upstream Tauri issue [#7533](https://github.com/tauri-apps/tauri/issues/7533) and the still-open fix PR [#15118](https://github.com/tauri-apps/tauri/pull/15118). GitHub CLI creates or updates a draft release only after Gatekeeper accepts the final DMG.

**Tech Stack:** GitHub Actions, macOS/Xcode `security`, `notarytool`, `stapler`, `spctl`, Tauri CLI 2.11, npm, Rust, GitHub CLI.

## Global Constraints

- Trigger only for pushed tags matching `v*`.
- The tag without its leading `v` must exactly equal the versions in `package.json`, `src-tauri/tauri.conf.json`, and `src-tauri/Cargo.toml`.
- Run `npm run lint`, `npm run format`, `npm run typecheck`, `npm run test`, and `(cd src-tauri && cargo test --lib)` before using signing credentials.
- Produce only `Sheltie_<version>_universal.dmg`; do not produce separate architecture-specific release assets.
- Use GitHub environment `release`; configure its deployment tag pattern as `v*` and do not require a reviewer.
- Create a draft release with GitHub-generated release notes. Publishing remains a manual action after installing the GitHub-downloaded DMG.
- Generate the checksum only after the DMG notarization ticket is stapled, because stapling changes the DMG bytes.
- Never print the `.p12`, `.p8`, their base64 encodings, or certificate password in logs.
- Pin all GitHub Actions to full commit SHAs with the corresponding major-version comment.
- Preserve unrelated worktree changes, especially the active MCP plans.

### Task 1: Add the macOS release workflow

**Objective:** Turn a matching version tag into a verified draft GitHub Release without exposing Apple credentials.

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: pushed `v*` tag, `release` environment secrets/variables, the three project version files, and the Developer ID/App Store Connect credentials.

- [ ] **Step 1: Create a least-privilege workflow skeleton**

Create `.github/workflows/release.yml` with:

```yaml
name: Release macOS

on:
  push:
    tags:
      - "v*"

permissions:
  contents: read

concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false

jobs:
  release-macos:
    name: Build signed macOS release
    runs-on: macos-latest
    environment: release
    permissions:
      contents: write # Required to create the draft release and upload its assets.
    env:
      APPLE_SIGNING_IDENTITY: "Developer ID Application: Ryo Nakae (ELFWBE4NMA)"
      APPLE_TEAM_ID: "ELFWBE4NMA"
      APPLE_API_KEY: ${{ vars.APPLE_API_KEY }}
      APPLE_API_ISSUER: ${{ vars.APPLE_API_ISSUER }}
    steps:
      - name: Check out release tag
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7
        with:
          persist-credentials: false

      - name: Set up Node.js
        uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v6
        with:
          node-version: 22
          package-manager-cache: false
```

Do not add pull request or manual triggers. Keep the workflow-level permission read-only and elevate only the release job to `contents: write`.

- [ ] **Step 2: Validate the tag and all project versions**

Add a Bash step that strips the leading `v`, reads the two JSON versions with Node, reads only the Cargo `[package]` version with `awk`, rejects empty values, and fails unless all three equal the tag version. On success, append `VERSION=<value>` to `$GITHUB_ENV`.

Use this complete script:

```bash
set -euo pipefail

if [[ ! "$GITHUB_REF_NAME" =~ ^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?(\+[0-9A-Za-z.-]+)?$ ]]; then
  echo "Unsupported release tag: $GITHUB_REF_NAME" >&2
  exit 1
fi

TAG_VERSION="${GITHUB_REF_NAME#v}"
PACKAGE_VERSION="$(node -p "require('./package.json').version")"
TAURI_VERSION="$(node -p "require('./src-tauri/tauri.conf.json').version")"
CARGO_VERSION="$(awk '
  /^\[package\]$/ { in_package = 1; next }
  /^\[/ { in_package = 0 }
  in_package && /^version[[:space:]]*=/ {
    value = $0
    sub(/^[^=]*=[[:space:]]*\"/, "", value)
    sub(/\"[[:space:]]*$/, "", value)
    print value
    exit
  }
' src-tauri/Cargo.toml)"

for entry in \
  "package.json:$PACKAGE_VERSION" \
  "src-tauri/tauri.conf.json:$TAURI_VERSION" \
  "src-tauri/Cargo.toml:$CARGO_VERSION"; do
  file="${entry%%:*}"
  value="${entry#*:}"
  if [[ -z "$value" || "$value" != "$TAG_VERSION" ]]; then
    echo "$file version '$value' does not match tag version '$TAG_VERSION'" >&2
    exit 1
  fi
done

echo "VERSION=$TAG_VERSION" >> "$GITHUB_ENV"
```

- [ ] **Step 4: Import the certificate and materialize the API key**

Add one credential-preparation step. Map the three secrets only into this step. Validate that environment variables and secrets are non-empty without printing them. Decode the `.p12` and `.p8` into `$RUNNER_TEMP`, create a random-password temporary keychain, import the certificate, allow `codesign`, and verify the exact signing identity.

```yaml
      - name: Prepare Apple signing credentials
        env:
          APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}
          APPLE_CERTIFICATE_PASSWORD: ${{ secrets.APPLE_CERTIFICATE_PASSWORD }}
          APPLE_API_KEY_BASE64: ${{ secrets.APPLE_API_KEY_BASE64 }}
        run: |
          set -euo pipefail

          for name in \
            APPLE_CERTIFICATE \
            APPLE_CERTIFICATE_PASSWORD \
            APPLE_API_KEY_BASE64 \
            APPLE_API_KEY \
            APPLE_API_ISSUER; do
            if [[ -z "${!name:-}" ]]; then
              echo "Missing release environment value: $name" >&2
              exit 1
            fi
          done

          CERTIFICATE_PATH="$RUNNER_TEMP/sheltie-developer-id.p12"
          API_KEY_PATH="$RUNNER_TEMP/AuthKey_${APPLE_API_KEY}.p8"
          KEYCHAIN_PATH="$RUNNER_TEMP/sheltie-build.keychain-db"
          KEYCHAIN_PASSWORD="$(openssl rand -hex 32)"
          echo "::add-mask::$KEYCHAIN_PASSWORD"

          printf '%s' "$APPLE_CERTIFICATE" | base64 --decode > "$CERTIFICATE_PATH"
          printf '%s' "$APPLE_API_KEY_BASE64" | base64 --decode > "$API_KEY_PATH"
          chmod 600 "$CERTIFICATE_PATH" "$API_KEY_PATH"

          security create-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security set-keychain-settings -lut 21600 "$KEYCHAIN_PATH"
          security unlock-keychain -p "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
          security import "$CERTIFICATE_PATH" \
            -k "$KEYCHAIN_PATH" \
            -P "$APPLE_CERTIFICATE_PASSWORD" \
            -T /usr/bin/codesign
          security set-key-partition-list \
            -S apple-tool:,apple:,codesign: \
            -s \
            -k "$KEYCHAIN_PASSWORD" \
            "$KEYCHAIN_PATH"
          security list-keychains -d user -s \
            "$KEYCHAIN_PATH" \
            "$HOME/Library/Keychains/login.keychain-db"
          security default-keychain -d user -s "$KEYCHAIN_PATH"
          security find-identity -v -p codesigning "$KEYCHAIN_PATH" \
            | grep -F "$APPLE_SIGNING_IDENTITY"

          echo "APPLE_API_KEY_PATH=$API_KEY_PATH" >> "$GITHUB_ENV"
          echo "BUILD_KEYCHAIN_PATH=$KEYCHAIN_PATH" >> "$GITHUB_ENV"
```

- [ ] **Step 5: Build the universal DMG and complete DMG notarization**

Run Tauri with the signing/notarization environment already exported. Tauri notarizes and staples the app. Then submit the generated DMG separately, wait for `Accepted`, staple it, validate the ticket, and require Gatekeeper to report acceptance.

```yaml
      - name: Build signed universal DMG
        run: npm run build -- --bundles dmg --target universal-apple-darwin

      - name: Notarize and verify DMG
        run: |
          set -euo pipefail

          DMG_PATH="$GITHUB_WORKSPACE/src-tauri/target/universal-apple-darwin/release/bundle/dmg/Sheltie_${VERSION}_universal.dmg"
          if [[ ! -f "$DMG_PATH" ]]; then
            echo "Expected DMG was not created: $DMG_PATH" >&2
            exit 1
          fi

          xcrun notarytool submit "$DMG_PATH" \
            --key "$APPLE_API_KEY_PATH" \
            --key-id "$APPLE_API_KEY" \
            --issuer "$APPLE_API_ISSUER" \
            --wait
          xcrun stapler staple "$DMG_PATH"
          xcrun stapler validate "$DMG_PATH"
          spctl --assess \
            --type open \
            --context context:primary-signature \
            --verbose=4 \
            "$DMG_PATH"

          DMG_NAME="$(basename "$DMG_PATH")"
          CHECKSUM_PATH="$DMG_PATH.sha256"
          (
            cd "$(dirname "$DMG_PATH")"
            shasum -a 256 "$DMG_NAME" > "$(basename "$CHECKSUM_PATH")"
          )

          echo "DMG_PATH=$DMG_PATH" >> "$GITHUB_ENV"
          echo "CHECKSUM_PATH=$CHECKSUM_PATH" >> "$GITHUB_ENV"
```

- [ ] **Step 6: Create or safely update the draft release**

Support rerunning a failed workflow only while the matching release remains a draft. Refuse to overwrite assets on a published release.

```yaml
      - name: Create draft GitHub Release
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail

          if IS_DRAFT="$(gh release view "$GITHUB_REF_NAME" --json isDraft --jq .isDraft 2>/dev/null)"; then
            if [[ "$IS_DRAFT" != "true" ]]; then
              echo "Release $GITHUB_REF_NAME is already published; refusing to replace assets." >&2
              exit 1
            fi
            gh release upload "$GITHUB_REF_NAME" \
              "$DMG_PATH" \
              "$CHECKSUM_PATH" \
              --clobber
          else
            gh release create "$GITHUB_REF_NAME" \
              "$DMG_PATH" \
              "$CHECKSUM_PATH" \
              --draft \
              --generate-notes \
              --title "Sheltie $GITHUB_REF_NAME" \
              --verify-tag
          fi
```

- [ ] **Step 7: Always remove temporary credentials**

Add the final cleanup step with `if: ${{ always() }}`. Restore the login keychain when present, delete the temporary keychain, and remove the decoded certificate/API key files. Do not delete the runner's login keychain.


## Validation

- `.github/workflows/release.yml` triggers only on `v*` tag pushes and binds the job to environment `release`.
- Every third-party/official action reference is a full 40-character commit SHA.
- Quality gates precede credential preparation.
- The temporary keychain and decoded private files are removed under `always()`.
- App notarization remains handled by Tauri; DMG notarization/stapling is explicit and verified before checksum generation.
- Release creation is draft-only and idempotent only for an existing draft.
- `npm run lint`, `npm run format`, `npm run typecheck`, `npm run test`, and `(cd src-tauri && cargo test --lib)` all pass.

## Risks and Tradeoffs

- GitHub environment secrets are available to the job after environment policy evaluation, even though they are mapped only into the credential step. Restricting the environment to `v*` tags and limiting repository write access are part of the trust boundary.
- `macos-latest` may move to a newer macOS/Xcode image. The workflow intentionally tracks it so Apple notarization tooling remains supported; a future runner change can affect reproducibility.
- The release job intentionally avoids npm and Rust build caches. A clean build is slower but prevents untrusted cache contents from entering a signed release artifact.
- A public signing identity and team ID appear in workflow source; these values are already present in signed artifacts and are not authentication secrets.
- Draft releases remain mutable. Publishing is the manual integrity boundary; if repository immutable releases are enabled, immutability starts only after publication.
- The first tag push cannot fully validate GitHub Environment configuration locally. Missing values fail explicitly before certificate import, and the user must perform the first end-to-end run.
- Tauri PR #15118 is open as of 2026-07-17. Reassess the manual DMG step after upgrading Tauri, but remove it only after direct artifact validation.
